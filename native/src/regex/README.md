# chainner_regex: file map

The regex engine of chainner_ext in C: regex-syntax 0.7.2 and regex 1.8.4, as regex-py
(chainner_ext 0.3.10) reaches them. The spec is the
local, git-ignored `docs/superpowers/specs/2026-10-06-chainner-ext-c-design.md`, and the sources are in
`native/runtime/download/src`.

## Contracts

- `native/include/chainner_hir.h` is the front end's contract with the engine: HIR,
  Properties, the smart constructors, `chn_hir_parse`, the UTF-8 sequences and the word tests.
  It is private to `chainner_regex.lib`.
- `native/include/chainner_regex.h` is the engine API that chainner_ext (X3) and the capsule
  (X5) use. Its header comment fixes `regex_probe`'s I/O format.
- Cross-lane contracts live only in these two headers. A lane may add private headers next to
  its own `.c` files (for example `ast.h` or `prog.h`). Nothing is shared across lanes.

The module's sources are in `native/src/chainner_ext/` (X3). They mirror chainner_ext 0.3.10's
`crates/bindings/src`: `lib.c`, `regex.c`, `clipboard.c`, `convert.c`, `dither.c`,
`pixel_art.c` and `resize.c`. They build twice: `chainner_ext.pyd` into
`backend/src/chainner_ext/`, and `chainner_ext_c.pyd` (`CHAINNER_EXT_HARNESS`,
`PyInit_chainner_ext_c`) into `<build>/harness/`. Both are limited API 3.11 and link `python3.lib`,
`chainner_native`, `chainner_regex` and `user32`.

## Stubs

Until a lane replaces a file, its status functions return `CHN_HIR_ERROR_UNIMPLEMENTED` or
`CHN_REGEX_UNIMPLEMENTED`, and its other functions abort. The trivially exact ones are already
final: `chn_regex_string_drop`, `chn_regex_spans_drop`, `chn_regex_iter_init` and
`chn_regex_pos_translator_init`/`_drop`. `regex_probe` reports a stub with exit status 3.

## Building the regex targets alone

The regex lanes use their own build directory, which needs neither the lock nor the CPython runtime (the
conformance tool's `regex-probe` looks there first, then in `native\build`):

```powershell
& '.\native\Build.ps1' -BuildDirectory native\build-regex -Define CHAINNER_C_REGEX_ONLY=ON
native\build-regex\regex_probe.exe --mode default --prefilter on < in.jsonl > out.jsonl
```
